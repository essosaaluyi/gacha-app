# カードテーブル3D：必要なテクスチャ素材

対象：`lib/table-3d/cabinetTable3D.ts`（three.js のカードテーブル）
素材制作：Codex ／ 実装：Claude ／ 2026-11-13 改訂（実装後に必要な素材が減ったため全面更新）

## 0. 現状：ライトは全部なくなった

テーブルのライト計算は**完全に廃止**した（three.js の `MeshBasicMaterial`、トーンマッピングなし）。
テクスチャの1pxがそのまま画面の1pxになる。見た目は2Dのまま、めくりは3Dとして動く。

**そして、原画に写っている面は新規素材が要らなかった。**
テーブルのジオメトリは原画を逆投影して作ってあるので、カメラを順方向に回せば、各頂点が原画のどのピクセルから来たかが分かる。それを UV にすると、**原画がそのままテーブルの表面になる**（リサンプリングもゼロ）。

実測（原画と描画結果の全ピクセル比較、チャンネル最大差）：

| | 値 |
|---|---|
| 平均差 | 7.9 / 255 |
| 差 2 以内 | 57.6% |
| 差 5 以内 | 72.3% |
| 差 10 以内 | 81.0% |
| 差 40 超 | 4.6%（原画の1〜3px幅の光沢と、外周の輪郭に集中） |
| 描画回数 | 20回（仕様上限 24） |
| ポリゴン | 544（仕様上限 15,000） |

つまり**フェルト・真鍮の縁・ベイ枠・金のヘアライン・留め具・下部機構は、もう原画そのもの**。
当初依頼しようとしていた「外周の断面ストリップ」「ベイ枠の断面ストリップ」「天板」は**不要になった**。

## 1. 必要な素材は4点だけ

原画はテーブルを一方向からしか見ていないので、**カメラから見えない面には1ピクセルも情報がない**。
いま単色で埋めてある。これだけ描いてほしい。

### 共通ルール

- **遠近をつけない。** その面を正面から見た平面として描く。
- **陰影・映り込み・ハイライトは描き込む。** ライトは一切効かない。描いた絵がそのまま出る。
- 基準密度 **512 px = world 1.0**。
- 色空間 sRGB。原画 `/images/cabinet/production/card-table-premium-three-bay-center-only-1120x420.webp` と同じトーン。
- アルファなし（不透明）。形式 WebP。Safari で表示できる形式のみ。
- 置き場所 `public/images/cabinet/table3d/`。ファイル名は**必ずバージョン付き**（`*.v1.webp`）。
  本番の `public/` には1年の immutable キャッシュが付くので、同名上書きは禁止。

### 1-1. 井戸（ベイの中）の内壁

| | |
|---|---|
| ファイル | `bay-well-walls.v1.webp` |
| 寸法 | **1024 × 144 px** |
| 内容 | 4枚の壁を左から順に1枚に並べる：**奥壁 → 右壁 → 手前壁 → 左壁** |
| 各壁の幅 | 奥・手前 world 0.4512（=256px）、左右 world 0.4480（=254px） |
| 深さ | world 0.26（=133px。画像の上端が天板の高さ、下端が井戸の底） |
| 現状 | 単色 `#070d10` |

スロットをめくった瞬間と、カードが落ちた先に見える。全体に暗い（原画のスロット内側が `#0e1a1e` 相当）。
手前壁には留め具（world 幅0.155）が付くので、その影を描いてよい。3ベイ共通。

### 1-2. 井戸の底

| | |
|---|---|
| ファイル | `bay-well-floor.v1.webp` |
| 寸法 | **256 × 256 px** |
| カバー範囲 | world 0.4512 × 0.4480 |
| 現状 | 単色 `#03070a` |

ほぼ黒＋四隅の暗がり。

### 1-3. めくれる板の裏面 ★最優先

| | |
|---|---|
| ファイル | `bay-plate-back.v1.webp` |
| 寸法 | **512 × 512 px** |
| カバー範囲 | world 0.4512 × 0.4480 |
| 現状 | 表と同じ（原画のスロット内側）を裏にも貼っている |

**ここがいちばん効く。** 回転の途中で正面を向いて大きく見える唯一の面。
いまは表と同じ絵なので「裏返したのに同じ」に見える。機構の金具・ビス・梁など、裏側らしいディテールが入ると、
めくりが「板が回った」として読めるようになる。

### 1-4. 板の側面（厚み）

| | |
|---|---|
| ファイル | `bay-plate-edge.v1.webp` |
| 寸法 | **512 × 16 px**（横 world 0.4512、厚み world 0.014） |
| 現状 | 単色 `#4a7a80` |

回転のちょうど真横のとき、これしか見えない。細いが、ここだけで「厚みのある板」かどうかが決まる。
単色でも成立するので、優先度は低い。

## 2. 原画に残っている弱点（参考）

いまの描画は原画と同じなので、**原画の弱点がそのまま出る**。気になるなら原画側の改訂になる。

- 外周の輪郭（原画の上端 row 21 付近）：ジオメトリとの差が最大7px。ここだけ平均差 15.6。
- 手前の縁から下（row 300〜）：下部機構。平均差 14.0。原画でもほぼ黒。
- 1〜3px幅の光沢が数px ずれる箇所がある（差40超の 4.6% の大半）。原因未特定。

## 3. 実装側の責任（Claude）

- 原画のテクスチャ化（`tools/make-table3d-textures.mjs`：輪郭の色をにじませ、アルファを落とす）。
- UV の投影（`projectUV`）、新素材が来たときの UV 割り当てとタイリング。
- 完全無灯なので、回転中の板の明るさは変わらない。必要なら動く部品だけ暗くする処理を足す（未実装）。
- スロット四隅・カメラは変更しない（変更していないことを毎回実測で確認する）。
